AI Receptionist Demo

A reception-style chatbot trained on a real dental clinic's public website. Ask about the practice — and watch it refuse what a reception bot must not answer.

Try an example:

Guardrails on show

The bot answers from retrieved site content only, and hard-refuses three classes of question:

  1. Medical advice (diagnosis, dosage, treatment) → refusal, no advice.
  2. Pricing → refusal; it will not invent a price.
  3. Emergencies → immediate call-the-clinic redirect. Out-of-scope questions are refused rather than improvised.

Run the behaviour checks yourself

These are the eight golden cases from the pipeline's test suite, executed live against this page's engine:

  1. Saturday hours? — expect answer
  2. Location & parking — expect answer
  3. Children's dentistry — expect answer
  4. Medical advice (refusal) — expect refuse_medical
  5. Dosage (refusal) — expect refuse_medical
  6. Pricing (refusal) — expect refuse_pricing
  7. Emergency (redirect) — expect refuse_emergency
  8. Out of scope (refusal) — expect refuse_unknown

How this fits the pipeline

The pipeline is: crawl the business's public site (robots-honouring) → extract a knowledge base → retrieval Q&A with fixed guardrails → live hosted agent. This page is the same retrieval and guardrail engine that the offline test suite validates (8/8 golden cases, 12/12 unit tests), ported to the browser. A hosted live-agent build of the same rules is being validated separately.

Boundary

The sample business is Redbank Plains Dental, whose public pages were crawled on 2026-10-22 for this demo. It is not a client and has not endorsed this demo; answers quote its public content with source links. The bot is software and can be wrong — verify anything important directly with the clinic. This page makes no network requests: the knowledge base is embedded below and every answer is computed locally in your browser. Questions or takedown requests: hello@rodion.place.
