# x402 Forecast Endpoint (Prototype)

A Flask prototype for serving **synthetic demo data** behind the x402 payment protocol. The returned price paths are generated by a deterministic placeholder, not a forecasting model or live market feed. The payment middleware uses the official x402 Python SDK and a facilitator; local tests cover rejection paths, but a real paid request has not been verified end-to-end.

**Not production-ready yet.** Treat forecast values as demo output, not investment advice. Do not send real funds or rely on this endpoint until deployment, controlled recipient configuration, facilitator settlement, and a funded-wallet integration test are verified.

## Features

- **x402 payment middleware**: requests without a verified payment receive `402 Payment Required`
- **Operational basics**: Gunicorn configuration, structured JSON logging, health checks, environment-based configuration
- **Containerized prototype**: Dockerfile for repeatable local deployment
- **Tests**: pytest coverage for health/configuration and payment rejection paths; real settlement requires separate integration testing

## Quick Start (Local Development)

```bash
# Install dependencies
pip install -r requirements.txt

# Run development server
python app.py

# Test endpoints
curl -i http://localhost:5001/health
curl -i http://localhost:5001/
curl -i http://localhost:5001/forecast
# A normal request demonstrates the 402 challenge. A valid Payment-Signature
# must be created by an x402-compatible client and verified/settled by the facilitator.
curl -i http://localhost:5001/forecast
```

## Configuration

All configuration via environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `5001` | Server port |
| `WORKERS` | `2` | Gunicorn worker processes |
| `LOG_LEVEL` | `INFO` | Logging level (DEBUG, INFO, WARNING, ERROR) |
| `EXPECTED_NETWORK` | `eip155:84532` | Payment network (Base Sepolia testnet by default) |
| `EXPECTED_ASSET` | `usdc` | Payment asset identifier; configure the correct token for the selected network |
| `EXPECTED_PRICE` | `0.01` | Payment price in decimal USDC units; SDK converts to atomic units |
| `EXPECTED_PAYTO` | required | Controlled recipient address; startup fails if missing |
| `FORECAST_SYMBOL` | `BTCUSDT` | Trading symbol for forecasts |
| `FORECAST_HORIZON` | `90` | Forecast horizon in minutes |

## Production Deployment

### Docker

```bash
# Build image
docker build -t x402-forecast .

# Run container
docker run -d \
  -p 5001:5001 \
  -e EXPECTED_PAYTO=0xyourwalletaddress \
  -e LOG_LEVEL=INFO \
  x402-forecast

# Verify
curl http://localhost:5001/health
```

### Gunicorn (Direct)

```bash
# Install
pip install -r requirements.txt

# Run
gunicorn --config gunicorn_config.py app:app
```

### Behind Reverse Proxy (Caddy/Nginx)

The application is designed to run behind a reverse proxy that handles TLS termination.

**Caddy example:**
```caddy
forecast.yourdomain.com {
    reverse_proxy localhost:5001
}
```

## Endpoints

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/health` | GET | None | Health check for orchestration |
| `/` | GET | None | Service info and payment details |
| `/forecast` | GET | x402 Payment header | Returns forecast data |

### Payment flow and response formats

Do not construct a payment header by copying public fields. The `Payment-Required` response describes the server's current x402 requirements; it is not proof of payment and cannot authorize access by itself. Use an x402-compatible client to create a signed payment payload for the configured network and token. The server's official x402 SDK middleware asks the facilitator to verify and settle that payment before returning the protected forecast data.

**402 Payment Required:** a request without a valid, facilitator-verified payment receives HTTP `402` and x402 requirement headers. Treat those headers as a challenge for the client, not as a payment credential.

**200 OK (with valid payment):**
```json
{
  "symbol": "BTCUSDT",
  "horizon": 90,
  "status": "ok",
  "build_at_utc": "2026-10-15T02:15:00+00:00",
  "forecasts": {
    "1d": {
      "mean_path": {1760572800: {"price": 65123.45}},
      "sample_paths": [{1760572800: {"price": 65123.45}}],
      "prediction_interval_95": [{1760572800: {"low": 63123.45, "high": 67123.45}}],
      "uncertainty_bounds": [{1760572800: {"low": 64123.45, "high": 66123.45}}]
    }
  }
}
```

## Security and release status

- The application is wired to the x402 SDK resource server and facilitator; a fabricated payment header is not proof of settlement.
- The automated suite tests rejection of missing, malformed, and fabricated payment headers. It does **not** prove a real wallet payment can complete successfully.
- Before any production use, verify the selected network/token/recipient with the facilitator, run a funded-wallet integration test on testnet, verify settlement and replay behavior, and complete a deployment/security review.
- `EXPECTED_PAYTO` must be an address controlled by the operator. Never commit private keys or credentials.
- Use TLS behind a trusted reverse proxy and review rate limits, timeouts, logging, and operational alerts before public deployment.
- Forecast responses explicitly label `status=demo`, `data_source=synthetic_demo`, `is_synthetic=true`, and `not_investment_advice=true`. Output must not be presented as a validated trading signal.
